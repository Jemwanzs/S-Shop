# 12 · Reports

**Scope:** §26 · **Routes:** `/reports`, `/reports/:key` · **API:** `GET /api/reports`, `GET /api/reports/{key}[?format=xlsx]`

## Standard reports (23)

| Group | Reports |
|---|---|
| Sales | Sales Report · Sales by Product · Sales by Branch · Sales by User |
| Orders | Order Report |
| Stock | Stock Position · Stock Movement · Stock Valuation · Stock Transfer · Stock Adjustment · Barcode Inventory · Low Stock · Out-of-Stock |
| Customers | Customer Report · Customer Purchase History |
| Loyalty | Loyalty Points · Loyalty Redemption · Referral Report |
| Credit | Credit Sales · Credit Aging |
| Finance | Expenses · Profitability |
| Staff | User Performance |

## Filters (consistent across reports)
Today · Yesterday · This week · This month · This year · specific date · date range · Branch · Category · Product ·
User. Each report uses the filters that apply to it. Totals are calculated for every money and count column.

## Output
On screen (table on desktop, cards on phones) with a totals bar, **PDF** (A4, landscape for wide reports, branded
header, totals footer — generated in the browser) and **Excel** (`.xlsx` with formatted numbers, frozen header and a
totals row — generated by the server).

## Access
Each report needs `reports.view` plus the module permission it draws from (e.g. Credit reports need `credit.view`,
Profitability needs `sales.view_financials`). Exports need `reports.export`. Cost/profit columns are hidden from users
without `sales.view_financials` (Settings → Reports).

## Adding a report
Add one entry to `REPORTS` in `server/src/routes/reports.rs` (key, title, group, columns, SQL using the shared `params`
and `lines` CTEs). The UI picks it up automatically.
